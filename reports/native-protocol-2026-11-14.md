# 原生工具协议的分层诊断

## 范围与方法

继续使用已有 `qwen3:4b-instruct-2507-q4_K_M`、Ollama 0.15.6。从 11 月 4 日取消提案失败轨迹中取最后一次模型输入，保留历史订单工具结果和工具 schema，记录真实 HTTP 请求、响应及 ChatOllama 解析结果。诊断只调用模型，不执行返回的业务工具。

## 实际观察

| 条件 | Ollama 原始结果 | 框架解析 |
| --- | --- | --- |
| 原始完整上下文 | content 中为 action JSON，没有 tool_calls | 空工具调用列表 |
| 仅移除协议示例 | content 中为 proposal JSON，没有 tool_calls | 空工具调用列表 |
| 最小定向提示 | 原生 cancel_pending_order tool_calls | 正确解析名称与参数 |
| 完整上下文追加协议及查询范围说明 | 仍为 action JSON | 空工具调用列表 |
| 通用精简业务提示 | 文字声称准备提案，并询问确认 | 空工具调用列表 |
| 失败动作后的聚焦协议恢复 | 空 content，无 tool_calls | 空工具调用列表 |

最小提示明确点名了取消工具，也减少了业务政策；它改变了任务难度，只能证明相同模型和适配器能够传递这一原生调用，不能证明通用多轮业务已被修复。其他条件同样不能单凭一次输出证明稳定效果。

当前证据将已观察到的偏差定位在模型原始输出层，未发现 ChatOllama 丢失工具调用。模型为何在完整业务提示中选择文字而非原生通道，仍未得到充分因果解释。不能据此断言所有问题都是模型大小造成的，也不能宣称某条简短提示可普遍解决问题。

这些提示和恢复尝试没有成为生产默认行为。没有使用云 API、下载模型，也没有把普通 JSON 解析为可执行工具调用。

## 代码修复

已观察到的 action JSON 曾被图标记为 `answered`。现在当无原生调用、完整文本（可带 json 代码围栏）可解析为对象且 action 对应已知工具时，返回 `failed / non_native_tool_action`。解析仅用于识别协议错误，不提取参数执行，也不生成提案。

该检查针对已观察到的顶层 action 结构；并不识别所有自然语言虚假执行声明或任意嵌套 JSON。普通状态 JSON 仍允许作为答复。完整原始模型消息保留在轨迹中，CLI 显示失败原因并返回非零退出码。

新增两个失败复现与一个普通 JSON 反例；实现前两个复现失败，实现后全套 145 项工程测试通过。这改善错误分类和可观察性，本身不是任务成功率提升。

[原始 HTTP、解析结果及诊断脚本](evidence/protocol-20261114/)包含上述全部条件，文件名分别为 original、no_examples、minimal、reminder、compact、focused。源码快照对应本轮 Dev 的 manifest 文件哈希。

完整 Dev 使用原 repair-v5 配置、B2、9 道已见任务，工具筛选默认关闭。没有修改数据、用户脚本、预算、最终状态评分或沟通 rubric。新一轮属于开发回归；模型输出会受运行时机等影响，不能将与历史单次分数的变化直接归因于本次错误标记修复。未运行 Test。

## 完整 Dev 结果

沟通复核后端到端 **1/9**；写任务状态及确认 **2/7**；待复核 **0**。原始报告的 0/9 是三个客观通过候选尚未复核时的值，最终应查看 [reviewed-report.json](evidence/protocol-20261114/dev-B2/reviewed-report.json)。历史 V5 同为 1/9，本轮没有得到最终指标提升。

- 24：保留订单正确，但仅答红色棉质 T 恤，漏掉目标蓝色棉质与黑色涤纶两件，失败。
- 48：空气净化器实际退货及确认正确，但虚构 5–7 日退款时间，并错误称同一已申请退货订单内的吸尘器还能再次退货，失败。
- 69：实际取消、确认及礼品卡退款正确；余额 $62.00 → $2736.40，退款 $2674.40，与最终答复一致，通过。
- 其余题未达到必要状态、确认、转交或追问要求。

全部九题使用只读 SQLite 查询重新取得末态，核对哈希和原评分失败项一致。沟通复核继续采用 t6-v1 rubric，为辅助离线检查，非独立人工评审；每项复核绑定原始行哈希。原始结果、复核结果、业务差异审计和完整轨迹分别保留。

本轮 Dev 没有触发新增加的顶层 action JSON 检测，因此不能把状态通过数的变化归因于该修复。它解决的是之前定向诊断发现的状态标记漏洞。

## 下一步的边界

暂不继续盲目扩大提示词搜索，也不默认开启失败的工具筛选实验。后续最值得独立设计并验证的是：由应用根据真实回执展示执行事实，并对政策相关的最终说明建立明确检查，防止“写入正确但答复错误”。这还未实现；必须保留用户的附加查询要求，不能用固定成功模板绕过沟通评分。任何新方案仍需先在 Dev 验证，再登记版本；当前结果不能用于声称业务稳定。
