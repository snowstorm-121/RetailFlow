# 取消目标的表达测试与索引协议

## 诊断

在运行前固定八组消息与期望范围，覆盖否定取消、委婉撤销、替换目标、缩小范围、补充原因、查询、退货和变更后补原因。只测原生目标工具，不执行业务。原协议使用 316a582 的实现，正确登记 **3/8**。

失败不仅是意图理解：模型曾将订单号改一位，或抄错 source_quote；原校验正确拒绝了这些输出。其他失败包括空回复、把查询改写成取消文字 JSON、把退货误判为取消。

## 改动

新增默认关闭的 cancel_goal_references。模型仍通过原生 update_cancel_goal 返回范围，但改为引用用户消息与候选订单的零基索引。程序从原始用户消息解析字面订单编号并稳定去重，只把索引解析为原文中的编号和文本；不从普通模型 JSON 提取执行参数，不决定应该取消谁。

内部仍存 scope、order_ids、source_quote，已有目标冻结、恢复、逐笔确认及完成证据不变。新解析拒绝负数、布尔值、字符串、越界、重复索引及不符合原目标约束的引用。

同一批模型输出还暴露了两种语义错误：选中明确要求保留的订单，以及将纯退货原话当作取消依据。因此对两种协议均加有限拒绝规则：引用需包含取消用语，明确保留的订单不得进入取消目标。规则不自动生成其余目标，也不是通用否定解析器。

另修复两个工程问题：模型上下文白名单原先会删除登记结果中的 scope/order_ids/source_quote，现在保留这些实际解析结果；非法计划已进入工具验证却漏计 usage.tool_calls，现在计入该次尝试。合法调用统计认识索引协议，但任务成功条件不变。

正确登记为 **3/8 → 5/8**。剩余三组没有完成正确登记，不能把拒绝计作理解成功。索引版新增校验前有两个错误目标能通过结构检查，新增拒绝规则后，对这批已记录输出均被拒绝。该结论只针对这些例子，不保证任意表达都能被识别。

模型响应来自各一次调用，schema 和 prompt 已与落地实现逐项核对；拒绝规则对已保存输出做离线复核，没有隐藏额外采样或选择性删除失败。八组是开发诊断，不是新增八道正式任务，不属于官方 benchmark，也不足以说明统计稳定性。

## 验收与决策

先写失败测试验证复制引用解析、拒绝保留订单、禁止纯退货依据、目标字段上下文保留及非法工具计数，再实现。最终工程测试 **186 passed**；独立只读审查未发现本次范围内的重要缺陷。

索引协议保留为独立实验配置，常规 CLI 与既有取消目标配置不自动开启它。没有重跑完整 Dev，最近完整结果仍是此前 proposal-recovery 的 **3/9**，不将定向结果拼接成新的整体成绩。

[完整证据](evidence/goal-stability-20261117/)包含原始 HTTP、解析结果、八组期望、离线拒绝复核、业务两组配置及 manifest、完整轨迹、只读审计和源码快照。所有本批 manifest 文件哈希均已核对。

当前剩余问题是语义选择和原生协议可靠性：委婉撤销无调用、替换目标选错、退货误分类。继续扩展通用任务目标前，应先处理这些边界，而不是用索引成功率代替业务成功率。
